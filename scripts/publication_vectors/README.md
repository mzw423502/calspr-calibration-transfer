# True-vector publication figures

This optional post-release helper exports final manuscript Figures 1 and 3 as genuine vector PDF/SVG files from the source code and frozen source tables already included in this repository. It does not alter the version 2.4.1 scientific archive or any original manifest.

Run on Linux from any checkout location. The tested environment is Kylin V11 x86_64 with Python 3.12.3, NumPy, Pillow 10.2.0, pycairo 1.25.1 / Cairo 1.18.0, DejaVu Sans regular/bold fonts in `/usr/share/fonts/truetype/dejavu`, and Poppler `pdfimages` / `pdftoppm`. These are additional rendering dependencies; scientific dependencies remain in the existing requirements files. No GPU is used. Nothing is installed by the helper.

From the repository root:

```sh
sh scripts/publication_vectors/run_true_vectors.sh /absolute/path/to/new_vector_output
```

The output path must be absent or empty and must lie **outside** this repository. An existing nonempty output, run log, status file or QA result is never overwritten. Use a fresh output path for every run. `CALSPR_VECTOR_PYTHON` optionally selects a Python executable. The wrapper limits CPU threads to one and prevents import-generated bytecode inside the repository.

The log and exit-status files are adjacent to the output directory: `<output>.run.log` and `<output>.exit_status`. The log records the actual rendering/audit commands, UTC start/end, output path, software versions, deterministic seed status and exit code. The output manifest records all source hashes, software versions and exports. Inspect exit status 0 and `vector_geometry_and_data_audit.json: all_pass=true` before using the output.

## Outputs and validation

- `Figure1.pdf` / `Figure3.pdf` are the standalone vector submission artwork. SVG copies are also supplied. All text is represented by vector outlines, and both formats contain zero raster images.
- `Figure1_300dpi.png` / `Figure3_300dpi.png` are previews for manuscript documents. They are not the line-art submission masters.
- `Figure1_PDFproof.png` / `Figure3_PDFproof.png` are actual PDF rasterizations for visual review. `panel_crops/` supplies per-panel previews and comparison crops from the approved rasters.
- `native_reconstruction_audit.json` requires the original drawing plus approved display fixes to reconstruct both previously approved Pillow figures pixel-for-pixel before vector replay. Cairo antialiasing differs, so its preview is not claimed to be pixel-identical.
- `plot_data_audit.json` must equal the approved plot audit. The vector geometry audit checks visible text boxes and retains all 63 paired means/complete intervals in Figure 3c.
- `*_drawing_commands.json`, `*_pdfimages.txt` and `manifest.json` preserve drawing and format evidence. No fitted CSV or original graphic is modified.

Both source directories' CSV copies are hash-compared before rendering. The helper reads the archived author-cleanup renderer, `scripts/figures/fix_frozen_figures.py`, the model code/material input, the five frozen source CSVs, and the approved display-repair graphics. PNGs are read only for comparison and are never inserted into SVG/PDF.

Figure 1a's two deterministic reflectance display curves are evaluated with the original renderer and identical material/model settings (201 angular samples, 633 nm, 50 nm thickness, q = 1.333 / 1.338, 0.10-degree response, order-16 quadrature). Its native plot pixels must match the approved reference. No fit, optimizer, Monte Carlo run or information analysis is executed. All remaining numerical marks are drawn from stored CSVs. The display curve vertices are saved as `Figure1a_curve_vertices.csv`.

Repository-root discovery uses the script's own path; no original user's host, home directory, SSH alias or absolute project path is required. Do not move this directory independently of the repository. The original source hashes are checked again after rendering, and the helper fails if an input changed.

Inspect both composites, every panel crop and both PDF proofs after a successful machine audit. Text outlines preserve fonts across viewers; ordinary numerical overlap in Figure 3c remains unchanged because no jitter or scientific display transform is introduced.
